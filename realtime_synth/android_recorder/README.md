# Tang 演奏助手 · 安卓 1.3

安装 [TangRecorder-1.3.apk](dist/TangRecorder-1.3.apk)。与 1.2 使用同一包名和签名，versionCode 为 4，可覆盖升级并保留已录 WAV、上次的 PDF 和 MIDI。

## 在线曲谱

在“PDF 曲谱”或“MIDI 屏幕指引”卡片中点“从网址下载”，粘贴 HTTPS 文件直链，再点“下载链接”。手机可在连接板卡之前下载并预览。PDF 支持 20 MB、200 页，MIDI 支持 2 MB。文件加载成功后，沿用已有的发送和选轨按钮。下载中断、服务器返回网页或文件验证失败时，上次成功的曲谱仍可打开。

现场可以直接点“下载在线示范”，从 Mutopia Project 下载 Franciszek Horetzky 的《Pyrenese Melody》。排版者将此版本置于公有领域。PDF 是一页五线谱，配套 MIDI 经手机编译得到 54 个可演奏音符、108 个事件、20.68 秒，会提示略过 27 个半音。[来源 PDF](https://www.mutopiaproject.org/ftp/HoretzkyF/horetzky25/horetzky25-a4.pdf) · [配套 MIDI](https://www.mutopiaproject.org/ftp/HoretzkyF/horetzky25/horetzky25.mid)

## 32 白键音高设置

连接支持键位设置的 v32 固件，在“实体琴键”选择 A 和 B。编号从左至右为 H1～H32，对应的默认音高为 C2～F6。“查询 A”显示该物理键当前实际音高。先结束演奏、测试音和 Loop 并静音。实体扫描开启时，要等校准正常并实际松开全部白键，再点“交换 A 与 B”。关闭扫描时，可以在静音状态下配置。H15 和 H16 互换后，H15 发 D4，H16 发 C4。点“恢复默认音高”或重新给板卡上电，即可恢复原白键排列。

手机只在收到 `~J` 的 TKAK 能力回包后启用设置。旧固件继续使用各自支持的录音、MIDI 和 PDF 功能。此入口设置实体琴键，12 键小键盘仍按固定鼓组使用。

## PDF 曲谱

1. 板卡运行 v31 曲谱固件，App 连接后显示“曲谱显示已就绪”。App 使用安全的 `~P` 探测；旧版仍可使用原有功能，不会收到曲谱二进制数据。
2. 在“PDF 曲谱”点“选择 PDF”，选择手机已下载的 PDF，或点“示例 PDF”使用内置两页《小星星》。查看黑白预览和页码后，点“发送本页并显示”。等待进度到 100% 和板卡确认，屏幕进入全屏曲谱。
3. “上一页并发送 / 下一页并发送”会在手机处理并发送新的一页，翻页需要保持蓝牙连接。板卡只保留一页；换页开始时会退出全屏，失败时可点“发送本页并显示”重试，不会显示不完整的半页。
4. 点“返回演奏界面”，或短按旋钮 B / 板上 KEY.0，可退出全屏并保留该页。点“显示已传页面”可重新打开。点“清除板上曲谱”会清除板内页面，不删除手机上的 PDF。
5. 传完后可以断开手机继续显示本页、演奏或录音；换页和重新发送仍需手机连接。断电后需要重新发送。

PDF 限制为 20 MB、1～200 页；加密 PDF 请先另存为不加密的版本。手机保留最近一次导入的原 PDF，但只渲染当前页。页面等比例适配横向 1024×600 显示区域，预压缩为 1024×512 黑白位图，板卡展开后保持原比例。窄长页面会留白，横向大字号曲谱更易阅读；首版不提供裁切、缩放或乐谱识别。

手机采用 Android 官方 [PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)，解析与渲染都在后台。位图每行从左至右打包，1 表示黑、字节最高位对应最左像素；压缩采用 `(连续字节数 1～255, 字节值)`。整页原始数据为 65,536 字节，经 CRC32 校验后才允许显示。曲谱上传、MIDI 指令和录音传输互斥，上传完成后可以恢复录音或指引。若提示“板卡正在采集”，请结束采集后重试。

## MIDI 屏幕指引

1. 板卡运行 v30 / v31 屏幕指引固件后，配对并连接，等到“屏幕指引已就绪”。App 先用安全的 `~G` 查询能力；旧录音固件仍可录音，但不会启用指引按钮，也不会收到 MIDI 二进制数据。
2. 点“选择 MIDI”，可从手机的下载目录或系统文件提供器选择 `.mid/.midi`；也可以点“示例 MIDI”直接载入一段 24 秒的小星星。
3. 选择一条有旋律的音轨。预览显示可演奏音符、事件数、时长和略过的半音、越界音、打击乐音符。手机保留原音高。若含不可演奏音符，发送前会要求确认。
4. 点“发送曲目到板卡”，等待分包进度走完和“已传入曲目”。板内最多存 512 个事件（通常约 256 个完整音符），最长 655 秒。超限时应选较短曲目或单独导出一条旋律轨。
5. 使用“播放 / 暂停”“回到开头”“上一组音”“下一组音”和速度按钮控制。传完后可以断开手机，板卡自己计时；上电内置示范曲可直接使用，上传的曲目断电后需重新发送。本次 v30 为 SRAM 临时程序，断电后还需先重新下载 v30。

首版支持 SMF 格式 0/1、PPQN 时间制、速度变化、running status、音符力度为零的 Note On、延音踏板与同音重叠。所选音轨的 `TrackIndex` 决定颜色槽，不推断左右手。C2～F6 共 32 个自然音用于屏上指引。每个音符的开始与结束量化到 10 ms，极短音至少显示 10 ms。

上传使用逐包 CRC16、整曲 CRC32 和停等确认。ACK 丢失时发送完全相同的帧，FPGA 可识别重传。传输未完成或校验失败时，板卡保留之前提交的曲目。录音期间不发送曲目或指引控制；传完曲目后可以再录音。

App 接收连接探测、上传及控制操作返回的指引状态，与录音数据共用同一蓝牙连接；首版不持续同步板上播放进度，实时目标键和计时以板卡屏幕为准。

## 录音

这个 App 让安卓手机从 Tang Mega 60K 的 J14 蓝牙模块接收演奏录音。录音取自 FPGA 最终数字音频，包含琴键、鼓组、Loop 回放以及启用的混响、延迟、合唱。音频经经典蓝牙 SPP 持续发送，手机直接写入 WAV，只需授予“附近设备”权限。

## 安装和使用

1. 系统要求 Android 6 或更新版本。APK 使用本机开发签名，适用于这套设备的测试。
2. 在手机系统蓝牙里配对 `=BTNU1`，地址尾号为 `7BB6`。先在蓝牙调试宝或其他串口 App 里断开该设备，J14 模块每次供一台客户端连接。
3. 打开“Tang 演奏助手”，允许访问附近设备，点“连接板卡”。App 会自动测串口位宽并查询录音协议。板上可运行 v30 / v31 固件，录音也兼容 [v23 录音固件](../control_bt_recorder/README.md)、[v24 J9 电平表固件](../control_output_meter/README.md) 或 [v25 电平表换向固件](../control_meter_l8/README.md)。v22 仅支持文字控制。
4. 在板上选择“开始演奏”，需要实体琴键时启用扫描并松键校准。在 App 点“开始录音”，弹琴或敲鼓，观察电平和计时；点“停止并保存”，等到出现“录音已保存”。
5. 在“手机录音”中选择一段，点“试听”，或点“导出 WAV”后选择手机上的目标文件夹。录音先保存在 App 私有目录；要在卸载后保留，请先导出。

WAV 为单声道、16 位 PCM、16276 Hz。空白段会录成静音，单段最长约 10 分钟。录音期间屏幕保持点亮；离开 App 会停止录音。蓝牙中断、校验失败或缺帧时，已通过校验的连续部分保存为带“中断”字样的 WAV。还没有收到完整音频帧时不会生成空录音。

## 构建和验证

工程可以用 Android Studio 打开。命令行复现当前 APK 可使用 `python build_apk.py`，要求 JDK 17+、Android SDK Platform 35、Build Tools 35.0.0，可通过 JAVA_HOME 和 ANDROID_SDK_ROOT 指定位置。脚本使用本机私有的测试签名，在 dist 目录输出并验证 APK。没有第三方运行时依赖。

配套测试由 FPGA 工程的 `test_recording.py` 驱动。它让录音 RTL 通过实际串口收发逻辑发送音频帧，再用本 App 的 Java 解码和 WAV 写入代码处理同一份输出，以独立编解码参考逐样本比对。

实板验收：使用这台安卓手机连接 `=BTNU1`，用户确认“已录到并能试听”。当时板上为 v23，User Code `0x00008D36`。

本版新增的 JVM 测试在 `tests/GuideTest.java` 和 `tests/GuideSessionTest.java`。前者覆盖 MIDI 时间、重叠、踏板、排除统计、容量、CRC 和录音/ACK 混流；后者用相同的 RecorderSession 和模拟 SPP 流验证丢 ACK 重试、一次提交、一次切换、录音互斥及旧固件兼容。Android 专用类的测试替身仅在 `tests/stubs`，不打入 APK。

`tests/fixtures/demo-upload.hex` 由 Android 使用的实际 Java 编码器生成，共 24 帧请求、84 个事件、24 秒。FPGA 仿真已完整接收这份数据，生成的 24 个 TGAK 回包再由 `GuideAckTest.java` 解码确认进度、提交和播放。手机触屏操作与真实蓝牙链路的联合验收由实物测试记录单独标注。

1.2 新增 `ScoreTest.java`（RLE 边界、透明像素、位序、CRC 和 TGAK/TPAK 混流）及 `ScoreSessionTest.java`（实际会话、BEGIN/DATA/COMMIT/SHOW 丢回包重试、单次提交、与录音/MIDI 互斥、旧版兼容）。`ScoreFixture.java` 使用 App 的实际编码器生成 `tests/fixtures/score/score-upload.hex`：示例 PDF 第一页的 845 个完整请求，包含序号回绕；同目录保留原始页面、压缩字节和元数据用于 FPGA 逐字节交叉检查。此 fixture 的页面栅格由独立 PDF 渲染器生成，不将其宣称为真实安卓 PdfRenderer 的运行验收。

`ScoreAckTest.java` 已用 App 实际接收代码解码 FPGA 曲谱 RTL 针对这 845 个请求返回的全部 20,280 字节 TPAK；逐包核对序号、命令、状态、页码和累计接收进度，并确认最终 65,536 字节页面通过提交、进入显示状态。
