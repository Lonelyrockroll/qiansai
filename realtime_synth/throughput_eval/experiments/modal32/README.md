# 单音 32 分量验证

这份候选工程用 32 个独立演化的正弦分量合成一个琴键的音色。每个分量有自己的相位、频率比和随时间衰减的幅度。四条计算通道分八组处理它们，每帧把结果相加。比赛截图中的第二条路线按这种实际运算的分量计数。原 v26 钢琴为每键 16 个模态。

本文数据对应偏亮的演示音色。后续按原琴的起音与尾音重新调音，见[32 分量演奏钢琴](musical/README.md)。

## 吞吐量怎么算

50 MHz / 1024 = 48,828.125 Hz。一个键的 16 个分量都活跃时，每秒更新 781,250 次。每键 32 个分量都活跃时，同一采样率下达到 1,562,500 次。若保持其他条件不变，只把已有的声部重新分给一个键，整机总吞吐量不会增加。

32 个实体键中，前 24 个（C2–E5）在触发时可使用全部 32 个分量。其余八键依次为 30、27、24、21、20、18、16、15 个。高音键的高次分量超出 21.36 kHz 的合成保护线，会被抑制，避免折返到错误音高。衰减到零的分量也不再计入活跃数量。[各键限带计算](coefficient_validation.json)

## 数字输出验证

| 测试 | RTL 仿真结果 |
|---|---|
| 只按一键，基频设为靠近 C4 的 262.26 Hz | 最终 PCM 有 32 个目标峰。最弱为 24.55 PCM 码，各峰比邻域背景至少高 32.67 dB。 |
| 单独关闭、改频第 12 分量 | 原峰下降 80.68 dB。改频后从 3,149.82 Hz 移到 3,221.35 Hz，其余 31 个目标峰幅度变化均小于 0.029 PCM 码。 |
| 同时按下 C2–F6 全部 32 个实体键 | 连续检查 4,096 帧。旋律引擎每帧用 577 / 1,024 拍，余量 447 拍。最终输出峰值 8,807 PCM 码，无超时、限幅或数字削波。 |
| 满键时内部活跃分量 | 该测试窗口共有 939 个限带后产生非零贡献的分量，折合每秒 45,849,609 次分量更新。许多频率彼此靠近或重合，落在 4,096 点 FFT 的 528 个不同近邻频点。939 不能直接作为分别可听辨的分量数申报。 |

单键频谱来自原 v26 混音、增益、限幅和实际帧节拍的数字仿真，效果旁路。[频谱图](evidence/single_note_32.png) · [验证数据](modal32_validation.json) · [单键频谱 CSV](evidence/single_spectrum.csv) · [满键频谱 CSV](evidence/full_chord_spectrum.csv)

单分量关断、改频通过测试用掩码和系数完成。它们用于证明一个分量能独立改变，当前演奏菜单尚无逐分量调节入口。

[C4 试听](audition/C4_AB_16_then_32.wav)用同一次击键条件和相同增益，先听候选音色的前 16 个分量，停 0.2 秒，再听全部 32 个。这里用实际 C4（261.63 Hz），样本取自音色内核的 RTL 输出。[试听生成方法](audition/README.md)

## 工程范围

此目录的完整工程对照只在隔离副本内替换钢琴内核，不会增加菜单项。字库压缩方案去掉空白行、重新编号字形，全部 6,624 个用到的字形行一致，和 v26 同一菜单场景逐像素对照，614,400 个像素均相同。原版 UI、Loop 和录音功能仍纳入整机编译。[字库对照](font_validation.json)

主候选用位置选项 2 完成 Tang Mega 60K NEO 的整机布局。逻辑占 36,741 / 59,904，寄存器 18,780 / 60,780，BSRAM 114 / 118，DSP 50.5 / 118。系统时钟目标 50 MHz，报告 Fmax 50.196 MHz。系统、USB、像素及串行时钟通过 setup/hold 检查，板端引脚沿用 v26。报告保留 PR1014 系统时钟通用布线警告。[布局报告](font_place2_report.json) · [候选码流与校验报告，User Code 0x000051EB](modal32_candidate.zip)

## C4 实板结果（2026-11-01）

用 JTAG 将主候选临时写入 SRAM，从器件回读 User Code `0x000051EB`。电脑通过正常演奏协议两次单独触发第 15 个白键 C4，使用 32 分量「敲击钢琴」音色和 25% 力度。FPGA 返回键位掩码 `0x00004000`，每次只有一个音符处于按下状态。采集点在最终数字 PCM、模拟功放之前。两次编号分别为 2 和 3，各自从不同的硬件帧起采，样本逐字节一致；样本读回的 CRC32 均与 FPGA 相符。[JTAG 回读](board_C4_20261101/candidate_jtag.log) · [采集、校验和恢复记录](board_C4_20261101/capture.json)

4096 点 Hann 窗下，两次均有 **32 / 32** 个预期频率通过局部峰值、幅度和信噪对照。拟合基峰为 261.57 Hz，第 32 峰为 8,423.13 Hz，32 个峰相对于系数表的最大频差为 0.193 Hz。最弱的第 32 峰幅度为 6.16 个 PCM 码，按 0.5 码的保守底线计算，余量为 21.82 dB。静音对照全部为零。现场如需检验耳机或音箱输出，应在模拟输出端另行测量。[实板频谱图](board_C4_20261101/c4_peaks.png) · [32 峰明细](board_C4_20261101/c4_peaks.csv) · [测量判据](board_C4_20261101/c4_peaks.json)

未经压缩的原字库方案需要 127 块 BSRAM，超出器件的 118 块。另一个可行方案保留原字库，把部分模态状态放到分布式 RAM，也已通过整机布局。[普通布局失败原因](place1_report.json) · [分布式存储候选](state_ram/README.md)
