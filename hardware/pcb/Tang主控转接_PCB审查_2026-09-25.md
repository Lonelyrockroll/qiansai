# Tang Mega 60K 主控转接：当前 PCB 电气审查

审查对象：`ProPrj_nos_pico_32key_repaired_2026-09-24.epro2`。

目标：保留 32 键霍尔、ADG732、两路 WS2812 灯链和四个辅助按键，通过排针连接 Tang Mega 60K，使 FPGA 成为主控。

本次为文件与资料审查，没有修改电路文件、没有给实物上电。结论：方案可行，现有 PCB 可以保留主体，但 ADC 接口、电源配置、输入上拉与接线定义必须明确后才能连接。

## 1. 必须处理的项目

### 1.1 ADC 输入不能照搬 Pico 接法

现有链路：

`霍尔 → ADG732 D端（U2.43）→ R1（2kΩ）→ ADC节点 → U1.11 / U1.12`

ADC 节点通过 R2（10kΩ）接地，C30（1nF）也从该节点接地。因此现有分压系数为 10/(2+10)=5/6，不适合直接接高云片内 SAR ADC 的 0～1V 单端输入。

若采用片内 SAR ADC，建议的首版数值是 **R1=10kΩ、R2=2kΩ，均选 1%**：

- 输入 5.0V 时，输出约 0.833V。
- 输入 5.5V 时，输出约 0.917V。
- 按上述 5.5V 和两电阻最不利 1% 公差计算，约 0.932V。

这些是正常输入范围的分压预算，不是对 ESD、误接 12V、上电尖峰的完整保护设计。还要核对实际 ADC 引脚、输入驱动能力、建立时间和共地方式，预留 ADC 测试点及合适的保护/缓冲位置。

**U1.11 与 U1.12 在 PCB 上已经短接为同一个模拟节点。只需选一个作为 ADC_OUT；另一个不能接成独立数字输出。**

片内 ADC 应使用 UG298 所描述的 SAR ADC 路径，不能把普通 GPIO 的高低电平读取当成模拟采样，也不能把慢速监测 ADC 的时钟直接当作有效采样率。

板卡资料中的 NEO 31004 底板，J11 是专用 ADC 接口，图纸标注为：1=ADCV_N、2=ADCV_P、3/4=GND、5=ADCT_N、6=ADCT_P。此处仅记录该版图纸，实物版本、1脚方向和核心板对应管脚仍需核对后才能制定正式接线/CST。

外接 ADC 也是可行替代路线：放在键盘侧或邻近的小转接板上，将数字 SPI 信号送往 Tang。但它的输入范围、采样速度、逻辑电平必须按所选 ADC 重新设计，不能同时照搬上述片内 ADC 分压数值。

### 1.2 单一供电方案必须落实到装配和标注

如果采用“不接键盘 USB，由 Tang 的 5V 输出供电”：

- 键盘 U1.19 为 +5V 输入；两板 GND 必须相连。
- JP1 必须保持开路，建议在专用 FPGA 版本中取消其短接功能或明确标注禁止短接。
- U3 是旧版 3.3V→5V 升压模块接口，本方案不安装升压模块。
- U1.16 的 +3V3 不是键盘板自带稳压输出；移除 Pico 后，这条网只连接 U1.16、U3.3、JP1.1。
- 若使用它给新增按键上拉供电，应由 Tang 的 3.3V 电源输入，且先处理 JP1/U3，避免连接到 5V。
- 键盘 USB VBUS 支路建议不装或预留可断开的跳线，避免日后误插造成双电源连接。

NEO 31004 的 `5V_Peripheral` 通过 U31，图纸限流标注为 1A，且由多个外设共享。它不是“每个排针都有 1A”。J13 的 11脚引出该 5V，12脚为 GND；PMOD 的供电脚则是 3.3V，不应混淆。

70 颗 RGB 灯的电流需要按实际器件和亮度计算。原项目中琴键灯、Logo 灯的封装/批次可能不同，不能把统一符号名当作同一额定电流。若采用每色 12mA 的 RGB 器件估算，70×3×12mA=2.52A，仅灯光就超过该外设支路能力；这只是相应器件条件下的预算示例。

若坚持只使用 Tang 的这条 5V 支路，需把灯光限亮、上电默认全灭、其它外设用电和实测余量作为设计约束。若要求大面积高亮，应增加独立、互斥选择的 5V 电源入口，而不是把两个 5V 输出并联。

D63 不处于 U1.19 的供电路径中。从 U1.19 输入可以绕过 D63，但不能绕过 Tang 的 U31 限流，也不能因此认定现有连接器/走线适合数安培电流。

### 1.3 四个辅助按键需要上拉

SW1～SW4 都是按下接地，当前 PCB 没有独立上拉电阻。原固件依赖 Pico 的 `gpio_pull_up()`。

移植必须二选一：

- 在 FPGA 引脚约束/配置中启用合适的内部上拉；
- 在板上或转接板上增加四路约 10kΩ 上拉至 Tang 的 3.3V。

不能上拉到 5V。RTL 中还需要输入同步和消抖，这两项不靠换排针自动获得。

### 1.4 排针必须区分电源、数字、模拟与 USB

不能按“原来都是 Pico 脚，所以都是可任选 GPIO”处理。供电脚、地、模拟节点、USB 数据线、悬空脚必须在丝印和接线表中分别标明。

建议将 U1/U5 改为清楚的连接器位号，并增加 1脚方向标记、`5V_IN`、`3V3_REF`、`GND`、`ADC_OUT`、`A0～A4`、`/CS`、`/WR`、两路灯光和四路按键标注。悬空脚明确标为 NC。

U1.2 与 U5.19 分别连到键盘 USB 的 D− 和 D+。本方案不使用 USB 时不接它们，不能视为普通外设信号。若以后需要 USB MIDI/HID，要另做 USB 设备控制器/接口方案。

## 2. 可以保留及建议完善的项目

### 数字多路复用控制可以保留

ADG732 在 5V 供电条件下的数字输入 VIH 最小值为 2.4V，VIL 最大值为 0.8V。满足输出电平规格的 Tang 3.3V GPIO 可以驱动 A0～A4、CS、WR，无须把这七根线全部升到 5V。

U2 的 EN 已接地，处于使能状态。CS/WR 的驱动时序应按数据手册处理；原固件采用 CS、WR 拉低的方式。FPGA 上电配置期间可通过约束或弱上下拉确定默认状态，防止控制线长期浮空。

### 灯光缓冲建议预留，是否必装取决于实际器件

查到的 Worldsemi WS2812B-4020 数据手册给出 VIH=2.7V，说明不能笼统认定所有 5V WS2812 都不能接收 3.3V 数据。实际仍要核对所购 4020/3528（或3535）型号、版本、FPGA VOH、线长与干扰余量。

稳定版本建议在两路灯光输入前预留 5V 供电、TTL 输入兼容的缓冲器，例如 SN74AHCT125 的两路，配合去耦、输入默认下拉和合适的源端串联电阻。它的输入高电平门限为 2V，适合接收 3.3V 控制信号。不要未经核对就换成门限不同的 74HC 系列。

缓冲器只需服务两条灯链的第一颗灯，后续 WS2812 自行转发整形。若两板需要独立开关电源，还需另外处理断电时的信号反灌；不能假设所选缓冲器自带断电隔离功能。

### C30、模拟走线和 LED 噪声

原 README 明确要求“不焊 C30”。当前工程仍保留 1nF 的符号/焊盘，因此应在装配说明或 BOM 中标记 DNP，不能只靠口头提醒。

若采用 R1=10k、R2=2k，1nF 电容对应分压节点的一阶时间常数约 1.67µs；切换通道后达到较高精度需要多个时间常数，不能认为等待 1µs 就足够。首版可先按原说明不装 C30，随后根据实测噪声和建立时间决定滤波值。

文件中 MUX 原始输出网及分压后采样网都有较长板上走线，还要叠加外接线。建议模拟线与地成对、尽量短；必要时在键盘侧增加缓冲或 ADC。保持连续地平面，并避免 LED 大电流回流影响 ADC 参考地，预留传感器电源滤波和灯光电源储能电容位置。

新增区域存在约 0.305mm 的供电支路线及局部 0.203mm 的短桥接段。这些主要承担新增单元的支路电流，不能仅凭线宽判定有问题，但应按铜厚、实际支路电流、压降和温升检查后再确定高亮能力。

### Tang 端不能随意选 IO Bank

数字控制应分配到确认供电为 3.3V 的 GPIO，并正确设置 CST。资料中的 FPC10P 接口位于 1.5V Bank，不能照搬 3.3V 数字接口接法。

模拟采样必须选择实际支持并已引出的 ADC 通道。官方全引脚 CST 是接口资料，不代表其中所有引脚可同时使用；PMOD、DVP、排针等存在复用。

## 4. 推荐的最小实现与验收顺序

1. 明确单一5V来源、JP1开路和U3不装，测量空载及亮灯负载下的板端5V。
2. 采用片内SAR时先修改R1/R2和ADC接线，确认全行程/全部通道不会超过ADC范围。
3. 以单键起步，验证通道选择、建立时间、ADC完成握手和原始数据，再扩展32键；可先以整轮约1ms为设计目标，而非未经测量就追求最快扫描。
4. 补足按键上拉，验证四个辅助键在未按下时稳定为高。
5. 单独验证两条灯链；随后在灯光变化时重新检查霍尔噪声、误触发和力度估计。
6. 最后完成上电默认状态、校准、同时按键及掉电恢复测试。

扫描顺序若沿用现有物理键位，应保留原映射 `0～15、27～16`，再追加 `28、29、30、31`。琴键灯为64颗，Logo灯为6颗。标定参数须在ADC量程改变后重新生成，不能原样沿用Pico的读数阈值。

这些修改可落在主PCB或小型转接板上，无须改变“排针连接Tang主控”的总体方案。若采用小转接板，优先让模拟处理靠近键盘，供电/数字连接有明确方向和丝印。

本审查没有给出未经实物版本确认的 Tang FPGA 球脚号，也不等同于实板验证。音源合成、I2S DAC 等赛题要求属于后续整机功能，需要另行实现。
