# 演奏延迟与琴键力度验证

从工程根目录运行 `python tests/contest_latency/run.py`。需要 Python 3.10+、Icarus Verilog 和 `vvp`。日志、按工况拆分的 CSV 和 RTL 输入哈希写入 `results/`。本测试不连接开发板。

## 计时边界

赛题要求控制信号到音频输出不超过 10 ms，拓展目标为 5 ms。项目最新技术问答表第 115 条明确要求 FPGA 延迟满足指标，并建议对传感、扫描、通信和后端按实际条件分段测量。第 119 条第①项引用第 115 条。当前没有统一的整机正式起止口径，应同时写明端点、测试设置和证据类型。

本测试驱动 `synth_display_top` 的实际音频数据通路，在 50 MHz 下运行 32 键扫描、通道切换等待、首样弃用、双转换平均、迟滞触发、事件仲裁、Loop 直通、声部分配、DDS 或 32 分量钢琴、混音、限幅、效果旁路和串行音频输出。外部 Hall 和片内模拟 SAR 用行为模型代替。每次接受 SOC 时锁存该物理通道的输入码，20 个系统时钟后返回有效码与 EOC。使用独立示波器或逻辑分析仪仍须实测真实转换/建立时间。

原来的[白键回归](../../realtime_synth/control_white_keys/tb_white_keys.v)缩短扫描槽以验证键号和画面，[串行音频回归](../output_trim/tb_quad.v)验证格式与位序，[耳机口实录](../../OUTPUT-HARMONICS.md)用于评估持续音失真。这些记录各自有用，但没有同时记录动作阈值和对应音频端点，不能从中读出端到端延迟。

CSV 中的时间以 ns 表示，除 `motion_to_threshold_ns` 外，均从**模拟输入码首次越过当前琴键的按下阈值**计起。

| 字段 | 实际含义 |
|---|---|
| `motion_to_threshold_ns` | 此次动作开始至阈值的时间。阶跃为 0，慢速移动需先积累有效行程。 |
| `kept_aperture_ns` | 第一次被扫描器保留、输入码达到阈值的 SOC 采样时刻。 |
| `scanner_handshake_ns` | 实体键 Note On 被主通路接受。此时已完成 SAR 模型的 EOC、平均和阈值判断。 |
| `engine_handshake_ns` | 路由器把这次门控、频率和力度交给合成器。 |
| `pcm_ns` | 最终数字混音首次产生非零 PCM。 |
| `pt_word_ns` | 在板载 PT8211 的 BCK/WS/DIN 全部收齐第一个含音乐信号的 16 位字。解码时扣除该子帧的直流偏置。 |
| `i2s_word_ns` | 按 I²S 的一位延迟，从外部 BCLK/LRCLK/DATA 收齐首个非零左声道 16 位字。 |
| `i2s_abs16_ns` | 首个绝对值至少为 16 个数字码的完整 I²S 左声道字。这个工程阈值便于复查微小起音，与耳机的听觉阈值不同。 |

测试使用松键基线 4000 码和按下阈值 256 码，无背景音，Loop 停止，效果旁路。正常演奏组先完成 16 轮校准和功放预热。每个独立试例开始前清除上一音的尾音，测量期间不强制任何扫描、事件、合成或串行输出值。C4 钢琴的阶跃分别落在一次扫描的不同位置，包括最后一次有效转换前、后相邻的时钟。另测 C2 和 F6。重复相同的上电、时钟、音高和触发相位，检查两次结果逐字段相同。

运行时序里音频帧固定 1024 个系统时钟，20.48 µs 一帧。本组测试观测到同一物理通道间隔 751 × 32 个系统时钟，即 0.48064 ms。动作可以在扫描和音频帧的任意位置发生。即使同相位回放完全一致，也不能把异步动作到输出的延迟写成“零抖动”。以 CSV 的相位范围和实测分布展示更准确。

板载观察页的数字 `ONSET` 从**扫描器 Note On 已被 FPGA 接受**时才开始计时，外部动作落入哪一次扫描的等待不在该数值里。TB 用音频节拍划分帧，在实际 BCLK 上升沿逐位检查 LRCLK 声道、I²S 一位延迟、填充和 DATA，再与板载 `onset_meter` 的结果独立比对。例如两次 C4 的事件到完整左字为 80.940 µs 和 84.780 µs，观察页显示 80 µs 和 84 µs。MARK 均在接受事件时升高，在实际 I²S 位末端后 20 ns 下降，符合系统时钟采认边沿所需的一拍。详见 `results/meter.json`。

`LAST I2S` 会保留最近一次完成的孤立音测量及其物理键号、计数。随后按下和弦不覆盖这个数，读取时要结合计数变化判断本次动作是否有新记录。

冷启动组先完成琴键校准，功放处于关断。在输入阶跃的同时开始演奏，从同一时刻报告 `amp_ready`、扫描确认及串行输出。若从给整块板上电计起，扫描器本身还需 10 ms 初始等待和约 7.69 ms 松键基线采集，另有 FPGA 配置、模拟功放与外设的启动时间，这些不计入已经就绪的演奏延迟。

| 已测试工况 | 数字延迟结果 |
|---|---:|
| 预热，C4 钢琴，9 个扫描相位，阈值至 I²S 首个非零字 | 0.085350～0.562130 ms |
| 预热，全部 18 个工况，阈值至 I²S 首个非零字的最大值 | 0.668730 ms |
| 同组，阈值至 I²S 首个达到 16 码字的最大值 | 0.975930 ms |
| 同组，阈值至板载 PT8211 首个含音乐信号的完整字的最大值 | 0.665930 ms |
| 冷功放、已校准，开始演奏与 C4 阶跃同时发生，至 `amp_ready` | 2.614450 ms |
| 同一冷功放工况，至完整 I²S 首个非零字 / 首个达到 16 码的字 | 3.049810 / 3.950930 ms |
| 从最慢斜坡**开始移动**算起，至 I²S 首个达到 16 码的字 | 7.127110 ms |

在这些孤立音符工况下，按电子阈值为起点，数字输出落在 5 ms 和 10 ms 之内；若改从最慢的动作起点计时，7.127110 ms 超过拓展的 5 ms。存在明显扫描相位差，因此不能以这些结果声称整机“确定性零抖动”。相同输入与时钟相位的回放、可编程逻辑的固定音频帧节拍，以及任意时刻按下琴键的响应散布，应分开陈述。

## 力度动态

每个物理键都有自己的三轮位移历史和峰值速度。琴键触发时使用相对速度，当前实现计算 `touch = clamp(speed × sensitivity, 4096, 16384)`，再用 `round(max_level × touch / 16384)` 得到声部力度。保持音量或音色时，仅改变运动速度即可改变实际振幅。这里的“速度”是 Hall 位移变化的代理量，并非标定的压力、牛顿值或每秒毫米数。

同一 C4 正弦音用每扫描轮次 20、42、100 个 ADC 码的三个斜率，分别在约 7% 和 25% 面板音量下测试；保持音色、音高、包络和输出增益一致。每次从实际 I²S 左声道字收集起音窗口（接受音符后 192 帧）的绝对峰值。这同时验证事件力度和最终声音幅度。以前直接把速度乘积钳在面板音量上限，导致低面板音量时较多动作提前封顶。

| 速度代理量（ADC 码） | 7% 事件力度 | 7% 串行峰值 | 25% 事件力度 | 25% 串行峰值 |
|---:|---:|---:|---:|---:|
| 60 | 1147 | 170 | 4096 | 606 |
| 126 | 2258 | 334 | 8064 | 1192 |
| 279 | 4588 | 678 | 16384 | 2421 |

表中三个速度在旧公式、7% 面板设置下分别得到 3840、4588、4588，后两个动作的事件力度相同。修正保留 25% 面板的原有力度范围，让低音量也能区分轻、中、重三种动作。这里报告的是实际 RTL 数字串行字峰值，未把它换算成喇叭声压。

实物验收应固定一个音，与三种动作对应地记录 `last_velocity` 和板端 PCM 起音峰值，各重复数次。默认灵敏度为 64，速度代理量约 64～256 码落在可调区间。若三种动作都封顶，可减小速度灵敏度；若都落在最低力度，可适当增大。再固定同一种动作改弹不同键，分别展示“选音”和“击键快慢”两个维度。本版力度在起音时锁存，不作为持续按压的 aftertouch 数据。

## 全松状态与路由恢复

**H15 长按的门级对照。** 旧版实板一次长按曾记录数百次 ON 而只有一次 OFF。复现时选用与工程相同的 Gowin Education 1.9.11.03 和 GW5AT-60B，将完整 `keyboard_input` 独立综合、布局并导出可读的 `.vo` 仿真模型。仅固定工作模式、阈值等配置端口，扫描、转换和管脚时序保留生产参数。TB 从复位开始经历真实启动等待和 16 轮基线校准，没有强制内部状态。将 H15 的模拟 ADC 输入从 4000 码升至 4720，持续 32 个完整扫描（15.38048 ms）再回到 4000，其他键始终为 4000。

| 扫描器 | 行为 RTL（ON/OFF） | 布局后 `.vo`（ON/OFF） | 长按期间错误清零的扫描数（共 32 轮） |
|---|---|---|---:|
| 原动态按位写法 | 1 / 1 | **16 / 0** | 16 |
| 当前单写者、整字操作 | 1 / 1 | **1 / 1** | 0 |

旧 `.vo` 的 H15 触发器在 `DECIDE`、键号 14、位移 720、原 Q=1 时，查表得到 D=0、CE=1、RESET=0，下一拍错误清为 0。到下次扫描它又发一个 ON。同样条件下，新模型的 CE=0，原值保持；仅在对应 `EMIT` 握手时写入 gate。这个隔离工程复现了数字综合后的一致性问题，可以解释实板长按时接近隔轮重发的症状；没有把加密的整机 `.vg` 当作已直接读取的门级证据，也未测量实际模拟噪声。`sensed_mask` 独立保留物理迟滞，在两种模型的长按阶段均持续检出 H15。

运行 `python tests/contest_latency/run_gate_hold.py` 可重建两个独立工程并分别运行 RTL / post-P&R 的同一组输入。该测试使用厂商功能仿真库，不加 SDF，不访问开发板。原始日志、扫描器及 `.vo` 哈希、三个 H15 局部查表结果见[长按对照记录](results/gate_hold/validation.json)。工具版本不同可能改变映射，现场应核对当前版本的行为。

`python tests/contest_latency/run_recovery.py` 检查两个功能。先通过真实扫描器触发 C4，给串行输出提供一个合成测试字，再按住第二个键形成和弦，核对 `LAST` 的键号、次数和原读数都保留。此段验证仪表的状态，不用来统计正常合成延迟。

随后由真实 Loop 播放器回放一层已准备好的数据，其内容为一个持续音及每个音频帧一次的鼓击。另一路也在竞争鼓输入。在物理琴键全松时，测试向实际路由器注入三个没有对应物理按键的 source 0 持有音。守护累计三个扫描边界以覆盖两整轮全松，在队列与路由空闲时只发出一次 source 0 屏障。三个残留归零，Loop 音仍被持有，回放持续进行了 154 个事件。其他来源的忙周期不会清除已累计的全松轮数，实际按住的琴键跨四个完整扫描轮次也不触发这项恢复。它用于重新对齐状态，不能单凭发生过恢复推断 Hall 噪声或丢事件的起因。

另一段压力测试使用非恒等白键排列、32 键和弦、72 组快速变化的输入掩码和竞争鼓事件，后端每 908 拍仅准备接受 4 拍。696 个真实扫描握手在路由端逐一对应，物理键 ID、映射后的相位步进和门控顺序正确，结束时物理、显示和路由掩码均为零。原始记录：[恢复回归](results/recovery.json)。

## 实物补测方法

1. 选择 C4，固定音色、输出音量和效果，松键校准。先开始演奏并完成预热。另做一组“同时开始演奏与触发”的记录，两组独立汇报。
2. 在多路开关前观测本次目标键的 Hall 输出，记录松键基线和与数字按下阈值对应的实物阈值。若只能测公共 ADC 输入，应同步记录复用地址并仅统计目标通道。不能把其他琴键切换造成的边沿算成本键触发。
3. 系统时钟下的扫描确认标志可作为分段参考点。当前观察页普通演奏模式将 `debug_sample`（约束管脚 AB22）切为 `onset_marker`；其脉宽是孤立音符从扫描握手到完整 I²S 非零字的板内计时。普通模式下该脚是采样节拍。连接器位置以所用底板的原理图和实物丝印为准。
4. 同一次采集记录 Hall 阈值、扫描标志、数字 I²S 和模拟 DAC/音频口起音，或按设备通道数分别完成相邻两段。模拟起音判据需事先固定，并报告空闲噪声水平。连续运行的 LRCLK 只能给出输出采样周期，不能作为发声起点。
5. 重复轻、中、重及不同触发相位，各记录最小值、中位数、P95、最大值和漏触发次数。实体键按下到听到声音还含机械行程、模拟传感、偏置、DAC、功放、扬声器与传播延时。当前证据不包含这段声学实测，也不覆盖开启纯湿效果或满负载 Loop 的所有组合。

## 用示波器 CSV 复核实物

[离线分析工具](../../tools/analyze_onset_csv.py)接受一个或多个 CSV，每个文件是**同一次采集、同一时基下的两路电压、一次孤立动作**。例如 CH1 取已核对的目标键 Hall 模拟输出，CH2 取 J25 音频口的模拟输出，可测 Hall 阈值到模拟起音。CH1 改取观察页的 MARK 则测扫描确认到模拟起音，在报告中应保留不同的起点名称。每次动作单独导出，保留静止、无声的预触发时间段。

以下命令使用仓库的两份**合成样例**演示用法，其中的阈值只用于工具自校验。现场请按实际列名、时间单位、基线以及两路电压的阈值设置。

```powershell
python tools/analyze_onset_csv.py tests/contest_latency/csv_examples/synthetic_rise.csv tests/contest_latency/csv_examples/synthetic_fall.csv `
  --time-column TIME_US --trigger-column HALL_V --audio-column OUT_V --time-unit us `
  --baseline -30 -10 --trigger-threshold-v 0.30 --direction either `
  --audio-threshold-v 0.08 --audio-points 3 --output scope-analysis.json
```

- `--time-unit` 支持 `s`、`ms`、`us`、`ns`，`--baseline` 的起止值使用该单位。输入电压列使用 V，输出时间统一为 ms。可用 `--delimiter tab` 或 `semicolon` 改分隔符。工具会查找包含指定三列的表头，可越过仪器导出文件开头的元数据行。
- 预触发区需要至少三点，分别取两通道中位数作基线。`--direction rising` 检测相对基线的正向变化，`falling` 检测负向，`either` 检测两种方向。`--trigger-points` 默认为 1，CH2 取相对其基线的绝对幅值。连续 `--audio-points` 个点越阈才确认起音，时间戳回填至其中第一点。
- `trigger_edge_ms` 和 `audio_edge_ms` 给出每个边沿前后两点的时间，`latency_ms` 是两路首个达标采样点的时间差。若两个边沿各在区间 `[a0,a1]`、`[b0,b1]` 内，采样分辨率允许的差值范围为 `[b0−a1,b1−a0]`。对非匀速采样也使用实际局部间隔。若两个边沿落在同一采样区间，点估计可能为零，应同时看区间和 `strict_order_resolved`；这项采样不确定度不包含探头、阈值选择和模拟电路的误差。
- 输出每次的结果与有效试验的最小、中位、最大和峰峰值。少于两次有效试验时峰峰值为 `null`。缺列、时间不递增、基线越阈、未触发、多次动作、背景音先起、确认点数不足或超过 `--max-delay-ms` 关联窗口都会报告原因，进程以非零状态退出。无效试验不计为零，汇总统计需结合有效数和尝试数一起看。

运行 `python tests/contest_latency/test_scope_csv.py` 可复核工具。合成样例期望延迟为 0.030、0.040 ms，中位数 0.035 ms，峰峰值 0.010 ms；在其 0.010 ms 的均匀采样网格上，各次差值的量化区间为点估计 ±0.010 ms。该自测还覆盖单点尖峰、采样间隔不均匀、同点触发和错误文件。**这些数值仅验证分析算法，不是开发板或乐器的测量结果。**
